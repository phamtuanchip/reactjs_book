Next.js — React Framework

Next.js là framework React phổ biến nhất, thêm SSR, file-based routing, API routes, image optimization và nhiều tính năng production-ready. App Router (Next.js 13+) là tương lai của Next.js.

22.3 Server Components vs Client Components

// Server Component (mặc định trong App Router)
// Chạy TRÊN SERVER — có thể access DB, file system trực tiếp
// KHÔNG có: useState, useEffect, event handlers, browser APIs

async function ProductPage({ params }: { params: { id: string } }) {
  // Fetch thẳng từ DB (chạy server-side, không cần API!)
  const product = await db.product.findUnique({
    where: { id: params.id }
  });

  if (!product) notFound(); // Next.js notFound()

  return (
    <div>
      <h1>{product.name}</h1>
      <p>{product.description}</p>
      <!-- AddToCart cần interactivity → Client Component -->
      <AddToCart productId={product.id} price={product.price} />
    </div>
  );
}

// Client Component — thêm 'use client' ở đầu file
'use client';
import { useState } from 'react';

interface AddToCartProps {
  productId: string;
  price: number;
}

function AddToCart({ productId, price }: AddToCartProps) {
  const [quantity, setQuantity] = useState(1);
  const [added, setAdded] = useState(false);

  const handleAdd = async () => {
    await addToCart(productId, quantity);
    setAdded(true);
  };

  return (
    <div>
      <input type="number" value={quantity} onChange={e => setQuantity(+e.target.value)} />
      <button onClick={handleAdd}>
        {added ? 'Đã thêm ✓' : `Thêm vào giỏ — ${price * quantity}đ`}
      </button>
    </div>
  );
}

22.4 Data Fetching Strategies

// 1. Static Site Generation (SSG) — build time
// fetch mặc định trong Next.js = cache forever (SSG)
async function BlogPost({ params }) {
  const post = await fetch(`https://api.example.com/posts/${params.slug}`, {
    cache: 'force-cache' // mặc định
  }).then(r => r.json());
  return <article>{post.content}</article>;
}

// 2. Server-Side Rendering (SSR) — mỗi request
async function Dashboard() {
  const data = await fetch('https://api/stats', {
    cache: 'no-store' // Không cache → SSR
  }).then(r => r.json());
  return <div>{data.visitors} visitors hôm nay</div>;
}

// 3. Incremental Static Regeneration (ISR) — cache có expiry
async function ProductsPage() {
  const products = await fetch('https://api/products', {
    next: { revalidate: 3600 } // Stale sau 1 tiếng → rebuild
  }).then(r => r.json());
  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

// 4. generateStaticParams — pre-generate dynamic routes
export async function generateStaticParams() {
  const posts = await fetch('https://api/posts').then(r => r.json());
  return posts.map(post => ({ slug: post.slug }));
  // Next.js sẽ build /blog/post-1, /blog/post-2... tại build time
}

22.5 API Routes

// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server';

// GET /api/users
export async function GET(request: NextRequest) {
  const searchParams = request.nextUrl.searchParams;
  const page = parseInt(searchParams.get('page') || '1');

  const users = await db.user.findMany({
    skip: (page - 1) * 10,
    take: 10,
  });

  return NextResponse.json({ users, page });
}

// POST /api/users
export async function POST(request: NextRequest) {
  const body = await request.json();

  const user = await db.user.create({ data: body });

  return NextResponse.json(user, { status: 201 });
}

// app/api/users/[id]/route.ts
export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const user = await db.user.findUnique({ where: { id: params.id } });
  if (!user) return NextResponse.json({ error: 'Not found' }, { status: 404 });
  return NextResponse.json(user);
}

export async function DELETE(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  await db.user.delete({ where: { id: params.id } });
  return new NextResponse(null, { status: 204 });
}

22.6 Metadata và SEO

// app/layout.tsx — Metadata mặc định
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: {
    template: '%s | My Shop',
    default: 'My Shop — Mua sắm online',
  },
  description: 'Mua sắm trực tuyến với hàng nghìn sản phẩm',
  openGraph: {
    type: 'website',
    locale: 'vi_VN',
    siteName: 'My Shop',
  },
};

// app/blog/[slug]/page.tsx — Dynamic metadata
interface Props {
  params: { slug: string };
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const post = await fetchPost(params.slug);

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: [{ url: post.coverImage }],
    },
  };
}

export default async function BlogPost({ params }: Props) {
  const post = await fetchPost(params.slug);
  return <article>{post.content}</article>;
}

Câu hỏi ôn bài

1. Khi nào một component trong App Router là Server Component?

  • A. Khi có prop "server={true}"
  • B. Mặc định — tất cả component trong app/ là Server Component trừ khi có 'use client'
  • C. Khi file có đuôi .server.tsx
  • D. Khi import từ server package

Đáp án: B — App Router mặc định là Server Components. Thêm 'use client' đầu file để chuyển sang Client Component. Chỉ thêm khi thực sự cần: useState, useEffect, event handlers, browser APIs.

2. SSG, SSR, ISR khác nhau thế nào?

  • A. Chỉ khác tên, hoạt động như nhau
  • B. SSG: build một lần; SSR: render mỗi request; ISR: build một lần, tự động cập nhật sau N giây
  • C. SSR nhanh nhất vì chạy trên server
  • D. ISR là viết tắt của Incremental Style Reloading

Đáp án: B — Blog: SSG (ít thay đổi). Dashboard realtime: SSR. Product catalog: ISR (revalidate mỗi giờ). Chọn theo tần suất thay đổi data và yêu cầu freshness.

3. File layout.tsx trong Next.js dùng để làm gì?

  • A. Khai báo CSS layout
  • B. Bọc các pages trong cùng route segment — giữ state giữa navigations, tái sử dụng UI (header, sidebar)
  • C. Khai báo cấu trúc database
  • D. Chỉ dùng cho root layout

Đáp án: B — Layout persist khi navigate giữa pages cùng segment — không unmount. Ví dụ: /dashboard/layout.tsx có sidebar → navigate từ /dashboard/profile sang /dashboard/settings giữ sidebar, không flash.

4. Tại sao Server Components tốt cho performance?

  • A. Chạy trên server nên nhanh hơn
  • B. Không gửi component code xuống browser — giảm bundle size; fetch data gần DB hơn; không waterfall network
  • C. Bỏ qua virtual DOM
  • D. Dùng bộ nhớ server

Đáp án: B — Server Components: zero JS bundle (chỉ HTML/JSON gửi về). Data fetch từ server → DB latency ms (không phải 100ms+ qua internet). Parallel data fetching dễ dàng. Client chỉ tải JS của Client Components.

5. generateStaticParams dùng để làm gì?

  • A. Validate params từ URL
  • B. Pre-generate tất cả dynamic routes tại build time để tạo static HTML
  • C. Generate random params để test
  • D. Khai báo kiểu của params

Đáp án: B — Thay vì SSR mỗi request cho /blog/[slug], generateStaticParams list tất cả slugs → Next.js build /blog/post-1, /blog/post-2... thành static HTML. Kết quả: tốc độ tải tức thì, CDN-cacheable.
