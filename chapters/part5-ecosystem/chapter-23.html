Authentication & Authorization

Authentication (xác thực danh tính) và Authorization (phân quyền) là core của mọi ứng dụng thực tế. Chương này bao gồm JWT, Session, OAuth, bảo mật và RBAC trong React/Next.js.

23.1 Authentication vs Authorization

sequenceDiagram participant U as 👤 User participant C as 🖥️ Client Browser participant S as 🔐 API Server participant DB as 💾 Database Note over U,DB: Đăng nhập lần đầu U->>C: Nhập email + password C->>S: POST /api/auth/login S->>DB: Tìm user, verify bcrypt hash DB-->>S: User found ✅ S->>S: Tạo JWT (userId, role, exp) S-->>C: Set-Cookie: token=JWT; HttpOnly; Secure C-->>U: Redirect → Dashboard ✅ Note over U,DB: Request tiếp theo — tự động auth U->>C: Vào /dashboard C->>S: GET /dashboard (cookie tự động kèm) S->>S: Verify JWT signature + expiry S-->>C: 200 OK + data C-->>U: Hiển thị dashboard

23.2 JWT (JSON Web Token)

// JWT structure: header.payload.signature (base64 encoded)
// eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOiIxMjMifQ.abc123...
//      ↑ header              ↑ payload              ↑ signature

// Payload chứa claims:
{
  "userId": "123",
  "email": "user@example.com",
  "role": "admin",
  "iat": 1700000000,  // issued at
  "exp": 1700086400   // expires (24h sau)
}

// KHÔNG bao giờ để sensitive data trong JWT (password, credit card...)
// JWT có thể decode mà không cần secret! Chỉ verify cần secret.

// Flow JWT:
// 1. User login → server tạo JWT với secret → trả về client
// 2. Client lưu JWT (localStorage hoặc cookie)
// 3. Mọi request: gửi JWT trong header Authorization: Bearer TOKEN
// 4. Server verify JWT (kiểm tra signature + expiry)

// API Route: Login (Next.js)
// app/api/auth/login/route.ts
import jwt from 'jsonwebtoken';
import bcrypt from 'bcryptjs';

export async function POST(request: Request) {
  const { email, password } = await request.json();

  const user = await db.user.findUnique({ where: { email } });
  if (!user) return Response.json({ error: 'Email không tồn tại' }, { status: 401 });

  const isValid = await bcrypt.compare(password, user.passwordHash);
  if (!isValid) return Response.json({ error: 'Mật khẩu sai' }, { status: 401 });

  const token = jwt.sign(
    { userId: user.id, email: user.email, role: user.role },
    process.env.JWT_SECRET!,
    { expiresIn: '7d' }
  );

  // Lưu trong httpOnly cookie (bảo mật hơn localStorage!)
  const response = Response.json({ success: true });
  response.headers.set('Set-Cookie',
    `token=${token}; HttpOnly; Secure; SameSite=Strict; Max-Age=${7 * 24 * 60 * 60}; Path=/`
  );
  return response;
}

23.3 Auth Context trong React

// contexts/AuthContext.tsx
'use client';
import { createContext, useContext, useState, useEffect } from 'react';

interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'editor' | 'user';
}

interface AuthContextType {
  user: User | null;
  isLoading: boolean;
  login: (email: string, password: string) => Promise<void>;
  logout: () => Promise<void>;
  isAuthenticated: boolean;
}

const AuthContext = createContext<AuthContextType | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [isLoading, setIsLoading] = useState(true);

  // Kiểm tra session khi load app
  useEffect(() => {
    async function checkAuth() {
      try {
        const res = await fetch('/api/auth/me');
        if (res.ok) {
          const data = await res.json();
          setUser(data.user);
        }
      } finally {
        setIsLoading(false);
      }
    }
    checkAuth();
  }, []);

  const login = async (email: string, password: string) => {
    const res = await fetch('/api/auth/login', {
      method: 'POST',
      body: JSON.stringify({ email, password }),
      headers: { 'Content-Type': 'application/json' }
    });
    if (!res.ok) {
      const err = await res.json();
      throw new Error(err.error);
    }
    const data = await res.json();
    setUser(data.user);
  };

  const logout = async () => {
    await fetch('/api/auth/logout', { method: 'POST' });
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{
      user, isLoading,
      login, logout,
      isAuthenticated: !!user
    }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth phải trong AuthProvider');
  return ctx;
}

23.4 Protected Routes và RBAC

// components/ProtectedRoute.tsx
'use client';
import { useAuth } from '@/contexts/AuthContext';
import { useRouter } from 'next/navigation';
import { useEffect } from 'react';

type Role = 'admin' | 'editor' | 'user';

interface ProtectedRouteProps {
  children: React.ReactNode;
  requiredRole?: Role;
  redirectTo?: string;
}

export function ProtectedRoute({
  children,
  requiredRole,
  redirectTo = '/login'
}: ProtectedRouteProps) {
  const { user, isLoading, isAuthenticated } = useAuth();
  const router = useRouter();

  useEffect(() => {
    if (isLoading) return;

    if (!isAuthenticated) {
      router.push(redirectTo);
      return;
    }

    if (requiredRole && user?.role !== requiredRole) {
      // Không đủ quyền
      router.push('/forbidden');
    }
  }, [isLoading, isAuthenticated, user, requiredRole]);

  if (isLoading) return <div>Đang kiểm tra quyền...</div>;
  if (!isAuthenticated) return null;
  if (requiredRole && user?.role !== requiredRole) return null;

  return <>{children}</>;
}

// Dùng trong pages
function AdminDashboard() {
  return (
    <ProtectedRoute requiredRole="admin">
      <div>Chỉ admin mới thấy trang này</div>
    </ProtectedRoute>
  );
}

// RBAC component helper
interface CanProps {
  role: Role | Role[];
  children: React.ReactNode;
  fallback?: React.ReactNode;
}

function Can({ role, children, fallback = null }: CanProps) {
  const { user } = useAuth();
  const roles = Array.isArray(role) ? role : [role];

  if (!user || !roles.includes(user.role)) return <>{fallback}</>;
  return <>{children}</>;
}

// Dùng trong component
function Navbar() {
  return (
    <nav>
      <a href="/">Trang chủ</a>
      <Can role={['admin', 'editor']}>
        <a href="/admin">Quản trị</a>
      </Can>
      <Can role="admin">
        <a href="/users">Quản lý users</a>
      </Can>
    </nav>
  );
}

23.5 Bảo mật — XSS và CSRF

// XSS (Cross-Site Scripting) — Chèn script độc hại
// React tự động escape JSX — an toàn mặc định
// NGUY HIỂM: dangerouslySetInnerHTML
<div dangerouslySetInnerHTML={{ __html: userInput }} /> // ← XSS!
// Nếu bắt buộc dùng, sanitize với DOMPurify:
import DOMPurify from 'dompurify';
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(html) }} />

// CSRF (Cross-Site Request Forgery) — Giả mạo request
// Cookie SameSite=Strict bảo vệ CSRF tốt nhất:
// Set-Cookie: token=...; SameSite=Strict; HttpOnly; Secure

// Middleware Next.js — kiểm tra auth cho tất cả protected routes
// middleware.ts (trong root, không trong app/)
import { NextRequest, NextResponse } from 'next/server';
import { verifyToken } from '@/lib/auth';

export function middleware(request: NextRequest) {
  const token = request.cookies.get('token')?.value;
  const isProtectedPath = request.nextUrl.pathname.startsWith('/dashboard');

  if (isProtectedPath) {
    if (!token) {
      return NextResponse.redirect(new URL('/login', request.url));
    }

    try {
      const payload = verifyToken(token);
      // Thêm user info vào header để Server Components đọc
      const response = NextResponse.next();
      response.headers.set('x-user-id', payload.userId);
      response.headers.set('x-user-role', payload.role);
      return response;
    } catch {
      return NextResponse.redirect(new URL('/login', request.url));
    }
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/dashboard/:path*', '/admin/:path*'],
};

Bài tập thực hành

Bài tập 23.1: Hệ thống Auth đầy đủ

// Xây dựng hệ thống auth với:
// 1. Đăng ký: name, email, password (hash với bcrypt)
// 2. Đăng nhập: email + password → JWT trong httpOnly cookie
// 3. Đăng xuất: xóa cookie
// 4. GET /api/auth/me: trả về user từ token trong cookie
// 5. AuthContext với useAuth hook
// 6. Protected routes: /profile, /settings
// 7. Admin-only routes: /admin
// 8. Hiển thị user menu khi đã đăng nhập
// 9. Refresh token tự động khi gần hết hạn
// Bảo mật:
// - HttpOnly cookie
// - bcrypt hash password (saltRounds=12)
// - Rate limiting cho /api/auth/login (max 5 requests/min)

Câu hỏi ôn bài

1. Tại sao nên lưu JWT trong httpOnly cookie thay vì localStorage?

  • A. Cookie nhanh hơn localStorage
  • B. JavaScript không thể đọc httpOnly cookie — bảo vệ khỏi XSS tấn công đánh cắp token
  • C. localStorage bị giới hạn kích thước
  • D. Cookie tự động expire

Đáp án: B — XSS attack: inject JS vào trang → document.cookie không trả về httpOnly cookies → không thể đánh cắp. localStorage: localStorage.getItem('token') hoạt động ngay với JS inject → nguy hiểm.

2. JWT có thể decode mà không cần secret không?

  • A. Không, cần secret để giải mã
  • B. Có — payload là base64 encoded, ai cũng có thể decode. Secret chỉ để VERIFY signature
  • C. Cần secret và public key
  • D. JWT được mã hóa hoàn toàn

Đáp án: B — JWT = base64(header) + "." + base64(payload) + "." + signature. Decode payload không cần secret. Vì vậy ĐỪNG để sensitive data (password, PII) trong JWT. Secret chỉ để kiểm tra token chưa bị giả mạo.

3. SameSite=Strict trong cookie bảo vệ khỏi tấn công nào?

  • A. XSS
  • B. SQL Injection
  • C. CSRF (Cross-Site Request Forgery)
  • D. Man-in-the-middle

Đáp án: C — SameSite=Strict: browser không gửi cookie khi request đến từ site khác. CSRF attack: evil.com gửi request đến bank.com (với cookie của user). Strict ngăn cookie được gửi từ evil.com → request không có auth → thất bại.

4. Middleware Next.js (middleware.ts) phù hợp để làm gì?

  • A. Xử lý business logic phức tạp
  • B. Kiểm tra auth/redirect trước khi routes render — chạy trên Edge, rất nhanh, không cần đến DB
  • C. Kết nối database
  • D. Render component

Đáp án: B — Middleware chạy ở Edge (Cloudflare Workers-like) trước khi request đến Server/Client. Phù hợp: auth check, redirect, A/B testing, i18n routing. KHÔNG phù hợp: DB queries (dùng Prisma/Mongoose trong API routes).

5. RBAC là gì và tại sao quan trọng?

  • A. React Bundle Access Control
  • B. Role-Based Access Control — phân quyền dựa trên vai trò, không kiểm tra từng user riêng lẻ
  • C. Runtime Browser API Check
  • D. Remote Backend API Configuration

Đáp án: B — RBAC: gán roles (admin/editor/user) cho users. Permissions gắn với roles, không với users cụ thể. Dễ quản lý: thay đổi quyền của 1000 editors chỉ cần sửa role "editor". Scalable hơn ACL (Access Control List).
