State và Event

State là "bộ nhớ" của component — dữ liệu có thể thay đổi theo thời gian và kéo theo UI re-render. Kết hợp state với xử lý sự kiện, bạn có thể tạo ra ứng dụng interactive thực sự.

11.1 State là gì?

Trong React, có hai loại dữ liệu: Props (dữ liệu từ component cha, chỉ đọc) và State (dữ liệu nội bộ component, có thể thay đổi).

// Props — dữ liệu từ ngoài vào (không thay đổi)
function Greeting({ name }) {
  return <h1>Xin chào, {name}!</h1>;
}

// State — dữ liệu nội bộ (có thể thay đổi)
function Counter() {
  const [count, setCount] = useState(0);
  // count thay đổi → component re-render → UI cập nhật
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

State phù hợp cho: giá trị form, trạng thái loading, dữ liệu đã fetch, toggle hiển thị, v.v.

11.2 useState Hook

import { useState } from 'react';

function Counter() {
  // useState trả về [giá trị hiện tại, hàm setter]
  const [count, setCount] = useState(0); // 0 là giá trị khởi tạo

  // Khi setCount được gọi:
  // 1. React lưu giá trị mới vào state
  // 2. Component re-render với giá trị mới
  // 3. UI cập nhật

  return (
    <div>
      <p>Đếm: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count - 1)}>-1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

Updater function — khi state mới phụ thuộc state cũ

// SAI — có thể bị stale closure
function handleClick() {
  setCount(count + 1);
  setCount(count + 1); // Cả hai đều dùng count cũ!
  // Kết quả: chỉ tăng 1, không tăng 2
}

// ĐÚNG — dùng updater function
function handleClick() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1); // Dùng giá trị mới nhất
  // Kết quả: tăng 2
}

// Khi nào dùng updater function?
// - Khi set state nhiều lần liên tiếp
// - Khi state mới tính từ state cũ
// - Trong async callbacks (setTimeout, fetch)

State với Object và Array

// Object state
const [user, setUser] = useState({ name: "An", age: 25 });

// Cập nhật một trường — phải spread toàn bộ!
setUser({ ...user, age: 26 }); // { name: "An", age: 26 }
setUser(prev => ({ ...prev, age: prev.age + 1 }));

// Array state
const [todos, setTodos] = useState([]);

// Thêm
setTodos(prev => [...prev, { id: Date.now(), text: "Mới", done: false }]);

// Xóa
setTodos(prev => prev.filter(t => t.id !== id));

// Toggle done
setTodos(prev => prev.map(t =>
  t.id === id ? { ...t, done: !t.done } : t
));
⚠️ Quy tắc vàng của State

KHÔNG bao giờ thay đổi state trực tiếp: user.age = 26 hoặc todos.push(item). Luôn tạo object/array mới. React so sánh tham chiếu để phát hiện thay đổi — nếu tham chiếu không đổi, UI không cập nhật!

11.3 Xử lý sự kiện

React sử dụng tên sự kiện dạng camelCase và truyền hàm (không phải chuỗi):

// Sự kiện cơ bản
<button onClick={handleClick}>Click</button>
<input onChange={handleChange} />
<form onSubmit={handleSubmit}>...</form>
<div onMouseEnter={handleHover} onMouseLeave={handleLeave}>...</div>
<input onKeyDown={handleKeyDown} onKeyUp={handleKeyUp} />

// Event object
function handleClick(event) {
  event.preventDefault(); // Ngăn default behavior (form submit, link...)
  event.stopPropagation(); // Ngăn bubble lên component cha
  console.log(event.target); // Phần tử kích hoạt event
  console.log(event.currentTarget); // Phần tử gắn handler
}

11.4 Controlled Components — Form

Trong React, form element nên là "controlled" — nghĩa là React kiểm soát giá trị hiển thị. State là "nguồn sự thật duy nhất" (single source of truth).

function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [error, setError] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault(); // Ngăn form reload trang

    if (!email || !password) {
      setError('Vui lòng điền đầy đủ thông tin');
      return;
    }

    // Gửi dữ liệu
    console.log({ email, password });
  };

  return (
    <form onSubmit={handleSubmit}>
      {error && <p className="error">{error}</p>}

      <label htmlFor="email">Email:</label>
      <input
        id="email"
        type="email"
        value={email}              {/* Giá trị từ state */}
        onChange={e => setEmail(e.target.value)} {/* Cập nhật state */}
        placeholder="example@email.com"
      />

      <label htmlFor="password">Mật khẩu:</label>
      <input
        id="password"
        type="password"
        value={password}
        onChange={e => setPassword(e.target.value)}
      />

      <button type="submit">Đăng nhập</button>
    </form>
  );
}
// Form phức tạp — một state object cho nhiều trường
function RegisterForm() {
  const [form, setForm] = useState({
    name: '',
    email: '',
    password: '',
    gender: '',
    agree: false
  });

  // Handler chung cho tất cả input
  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    setForm(prev => ({
      ...prev,
      [name]: type === 'checkbox' ? checked : value
    }));
  };

  return (
    <form>
      <input name="name" value={form.name} onChange={handleChange} />
      <input name="email" type="email" value={form.email} onChange={handleChange} />
      <input name="password" type="password" value={form.password} onChange={handleChange} />

      <select name="gender" value={form.gender} onChange={handleChange}>
        <option value="">Chọn giới tính</option>
        <option value="male">Nam</option>
        <option value="female">Nữ</option>
      </select>

      <input
        type="checkbox"
        name="agree"
        checked={form.agree}
        onChange={handleChange}
      />
    </form>
  );
}

11.5 State Lifting — Chia sẻ State

Khi hai component cần dùng chung state, đưa state lên component cha chung gần nhất (lift state up):

// Hai component con cần chia sẻ state
function TemperatureConverter() {
  const [celsius, setCelsius] = useState(0);

  const handleCelsiusChange = (value) => {
    setCelsius(Number(value));
  };

  return (
    <div>
      <CelsiusInput value={celsius} onChange={handleCelsiusChange} />
      <FahrenheitDisplay celsius={celsius} />
      <KelvinDisplay celsius={celsius} />
    </div>
  );
}

function CelsiusInput({ value, onChange }) {
  return (
    <label>
      Celsius:
      <input
        type="number"
        value={value}
        onChange={e => onChange(e.target.value)}
      />
    </label>
  );
}

function FahrenheitDisplay({ celsius }) {
  const fahrenheit = (celsius * 9/5 + 32).toFixed(2);
  return <p>Fahrenheit: {fahrenheit}°F</p>;
}

function KelvinDisplay({ celsius }) {
  const kelvin = (celsius + 273.15).toFixed(2);
  return <p>Kelvin: {kelvin}K</p>;
}

Câu hỏi ôn bài

1. Khi nào nên dùng updater function setState(prev => ...) thay vì setState(newValue)?

  • A. Luôn luôn dùng updater function
  • B. Khi state mới phụ thuộc vào state cũ, hoặc khi set state nhiều lần liên tiếp
  • C. Chỉ khi state là object hoặc array
  • D. Updater function và truyền giá trị trực tiếp là như nhau

Đáp án: B — Updater function nhận giá trị state mới nhất, tránh stale closure bug. Đặc biệt quan trọng khi: set state nhiều lần trong cùng handler, hoặc trong async callbacks.

2. "Controlled component" trong React là gì?

  • A. Component được kiểm soát bởi CSS
  • B. Form element có giá trị được kiểm soát bởi React state (value + onChange)
  • C. Component không thể thay đổi sau khi render
  • D. Component chỉ nhận props, không có state

Đáp án: B — Controlled: value={state} + onChange={handler}. React state là nguồn sự thật duy nhất. Uncontrolled: dùng ref để đọc giá trị DOM trực tiếp khi cần (ít phổ biến hơn).

3. Tại sao cần gọi e.preventDefault() trong form submit handler?

  • A. Để React có thể xử lý event
  • B. Để ngăn browser reload trang (hành vi mặc định của form submit)
  • C. Để ngăn event bubble lên component cha
  • D. Để validate form

Đáp án: B — Mặc định, khi submit form HTML, browser gửi request và reload trang. e.preventDefault() ngăn hành vi đó, cho phép xử lý bằng JavaScript (AJAX, React state).

4. "Lifting state up" nghĩa là gì?

  • A. Tối ưu hiệu năng của state
  • B. Đưa state từ component con lên component cha chung khi nhiều component cần dùng chung
  • C. Dùng global state thay vì local state
  • D. Convert state sang TypeScript type

Đáp án: B — Khi component A và B (anh em) cần dùng chung state, đưa state lên component cha chung. Cha truyền state qua props và callback handler xuống cho con. Đây là pattern chuẩn trước khi dùng Context hay Redux.

5. Đoạn code nào đúng để xóa item có id === 3 khỏi state array?

  • A. items.splice(items.findIndex(i => i.id === 3), 1)
  • B. delete items[2]
  • C. setItems(items.filter(i => i.id !== 3))
  • D. setItems(items.remove(3))

Đáp án: C — filter tạo mảng mới không chứa item có id=3. A và B đều mutate mảng gốc (sai). D: remove không tồn tại trong JavaScript.
