Giới thiệu React

Đây là bước ngoặt trong hành trình học của bạn — chúng ta chính thức bước vào thế giới React. Chương này giải thích tại sao React ra đời, cách nó hoạt động, và thiết lập môi trường phát triển đầy đủ.

9.1 Tại sao React ra đời?

Trước khi có React, lập trình web tương tác rất phức tạp. Hãy nhìn vào vấn đề thực tế:

// Cách làm truyền thống — Vanilla JavaScript
// Tưởng tượng một trang Facebook với hàng trăm component:
// - Like count cần cập nhật
// - Comment counter cần cập nhật
// - Notification badge cần cập nhật
// - ...

function updateLikeCount(postId, newCount) {
  document.getElementById(`like-${postId}`).textContent = newCount;
  document.getElementById(`like-icon-${postId}`).classList.toggle('active');
  // Còn phải cập nhật analytics, notification, ...
  // Code trở nên rất phức tạp và dễ bug!
}

// Mỗi khi state thay đổi → phải tự tay cập nhật DOM
// Rất dễ quên cập nhật một chỗ nào đó → bug

Facebook gặp đúng vấn đề này vào năm 2011. Họ tạo ra React để giải quyết: "Thay vì nói DOM phải thay đổi như thế nào, hãy chỉ mô tả UI trông như thế nào, và để React lo phần còn lại."

React giải quyết vấn đề gì?

  • Declarative UI: Bạn mô tả UI theo state hiện tại. React tự cập nhật DOM khi state thay đổi.
  • Component-based: UI chia thành các component tái sử dụng, dễ test và maintain.
  • Hiệu năng: Virtual DOM đảm bảo chỉ cập nhật phần DOM thực sự thay đổi.
  • Hệ sinh thái lớn: Cộng đồng khổng lồ, thư viện phong phú, nhiều việc làm.

9.3 Virtual DOM

Đây là "bí quyết" hiệu năng của React. Thao tác DOM thực rất chậm. React tạo ra một bản copy DOM trong bộ nhớ (Virtual DOM) và dùng thuật toán diffing để tính toán thay đổi tối thiểu.

flowchart TD SC["🔄 State / Props thay đổi"] --> NV["🆕 Virtual DOM mới (JavaScript object — rất nhanh)"] OV["📋 Virtual DOM cũ"] --> DIFF["⚡ Diffing Algorithm so sánh 2 cây"] NV --> DIFF DIFF -->|"Chỉ phần khác biệt"| PATCH["🎯 Minimal Patch"] PATCH --> RDOM["🌐 Real DOM — Browser (update tối thiểu)"] style SC fill:#282c34,stroke:#e5c07b style DIFF fill:#282c34,stroke:#61dafb style RDOM fill:#282c34,stroke:#98c379
💡 Virtual DOM không phải lúc nào cũng nhanh hơn

Virtual DOM có overhead tính toán. Nếu UI đơn giản, Vanilla JS có thể nhanh hơn. React tỏa sáng ở ứng dụng phức tạp với nhiều component và state thay đổi thường xuyên — ở đó React batch và tối ưu updates tốt hơn.

9.4 Cài đặt môi trường

Bước 1: Cài Node.js

Node.js là runtime JavaScript cho phép chạy JavaScript ngoài trình duyệt. npm (Node Package Manager) đi kèm với Node.js.

# Kiểm tra đã cài chưa
node --version   # Nên có v18+ hoặc v20+
npm --version    # v9+

# Nếu chưa có: tải tại nodejs.org (chọn LTS version)
# Khuyến nghị: dùng nvm (Node Version Manager) để quản lý nhiều version

Bước 2: Chọn package manager

# npm — có sẵn khi cài Node.js
npm install react     # cài package
npm run dev           # chạy dev server

# yarn — nhanh hơn, cần cài riêng
npm install -g yarn
yarn add react

# pnpm — tiết kiệm disk space nhất (khuyến nghị!)
npm install -g pnpm
pnpm add react

Bước 3: Tạo dự án với Vite

Vite là build tool hiện đại, nhanh hơn Create React App nhiều lần. Đây là lựa chọn tiêu chuẩn hiện nay.

# Tạo dự án React mới với Vite
npm create vite@latest my-react-app -- --template react

# Hoặc với TypeScript (khuyến nghị)
npm create vite@latest my-react-app -- --template react-ts

# Chạy dự án
cd my-react-app
npm install
npm run dev

# → Mở http://localhost:5173 trên trình duyệt

9.5 Cấu trúc thư mục dự án React

my-react-app/
├── public/                   # File tĩnh (favicon, robots.txt...)

├── src/                      # Code nguồn của bạn
│   ├── assets/               # Hình ảnh, fonts...

│   │   ├── Button.jsx

│   │   ├── Home.jsx
│   │   └── About.jsx

│   ├── utils/                # Helper functions

│   ├── App.css
│   ├── main.jsx              # Entry point
│   └── index.css             # Global styles

Các file quan trọng

// index.html — HTML duy nhất, React mount vào div#root
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>My React App</title>
  </head>
  <body>
    <div id="root"></div> <!-- React render vào đây -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
// src/main.jsx — Entry point
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App.jsx'
import './index.css'

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
)
// src/App.jsx — Root component
import { useState } from 'react'
import './App.css'

function App() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <h1>Xin chào React!</h1>
      <p>Bạn đã click {count} lần</p>
      <button onClick={() => setCount(count + 1)}>
        Click tôi
      </button>
    </div>
  )
}

export default App

9.6 React Developer Tools

Cài extension React Developer Tools cho Chrome/Firefox. Đây là công cụ debug không thể thiếu khi làm việc với React:

  • Components tab: Xem cây component, props và state của từng component.
  • Profiler tab: Đo lường hiệu năng, xem component nào render nhiều nhất.
  • Highlight component khi hover để biết nó render ở đâu trên trang.
💡 React StrictMode

<React.StrictMode> trong main.jsx giúp phát hiện các vấn đề tiềm ẩn. Trong development, React sẽ render component hai lần để phát hiện side effects không mong muốn. Đừng lo — điều này chỉ xảy ra ở development, không ảnh hưởng production.

Bài tập thực hành

Bài tập 9.1: Tạo và Khám phá dự án React đầu tiên

  1. Cài Node.js (nếu chưa có) và kiểm tra: node --version
  2. Tạo dự án mới: npm create vite@latest hello-react -- --template react
  3. Cài dependencies và chạy: cd hello-react && npm install && npm run dev
  4. Mở http://localhost:5173 trong trình duyệt
  5. Mở src/App.jsx và thay đổi:
    • Tiêu đề thành tên của bạn
    • Nút "click me" thành "Click tôi"
    • Xem thay đổi tự động cập nhật (Hot Module Replacement)

Bài tập 9.2: Cài React DevTools và Khám phá

  1. Cài React Developer Tools cho Chrome từ Chrome Web Store
  2. Mở dự án React ở trên
  3. Mở DevTools → Tab "Components"
  4. Click vào component App → xem state (count) thay đổi khi click nút
  5. Thử edit state trực tiếp trong DevTools

Câu hỏi ôn bài

1. Virtual DOM trong React là gì?

  • A. Một DOM đặc biệt chạy nhanh hơn DOM thực
  • B. Một bản copy của DOM trong bộ nhớ dạng JavaScript object, dùng để tính toán thay đổi tối thiểu
  • C. Một tính năng chỉ có trong React Native
  • D. Một cách để ẩn DOM khỏi người dùng

Đáp án: B — Virtual DOM là JavaScript object tree mô phỏng DOM thực. React so sánh Virtual DOM cũ và mới (diffing), sau đó chỉ cập nhật những phần DOM thực thực sự thay đổi (reconciliation).

2. Vite khác Create React App (CRA) ở điểm gì quan trọng nhất?

  • A. Vite chỉ hỗ trợ TypeScript
  • B. Vite nhanh hơn đáng kể vì dùng native ES modules trong development, không bundle toàn bộ
  • C. CRA tốt hơn cho production
  • D. Vite không hỗ trợ React

Đáp án: B — Vite dùng native ES modules của trình duyệt trong development mode → không cần bundle → khởi động gần như tức thì. CRA phải bundle toàn bộ app mỗi lần → chậm hơn nhiều với project lớn.

3. Tại sao React được gọi là "declarative"?

  • A. Vì bạn phải khai báo (declare) tất cả biến
  • B. Vì bạn mô tả UI trông như thế nào theo state, không cần chỉ định từng bước thay đổi DOM
  • C. Vì React declarate (khai báo) các thư viện cần dùng
  • D. Vì code React rõ ràng (clear) hơn JavaScript thông thường

Đáp án: B — Declarative: bạn nói "UI cần trông như thế này" (dựa trên state). Imperative: bạn nói "làm bước 1, bước 2, bước 3 để thay đổi UI". React lo việc "làm như thế nào", bạn chỉ cần lo "kết quả là gì".

4. File nào trong dự án React Vite là điểm vào (entry point) của ứng dụng?

  • A. src/App.jsx
  • B. index.html
  • C. src/main.jsx
  • D. package.json

Đáp án: C — src/main.jsx là nơi React được khởi tạo và mount vào DOM (ReactDOM.createRoot). index.html là HTML template, App.jsx là root component.

5. React StrictMode trong development sẽ render component bao nhiêu lần?

  • A. 1 lần (như bình thường)
  • B. 2 lần (để phát hiện side effects)
  • C. 3 lần
  • D. Không giới hạn

Đáp án: B — StrictMode render component 2 lần trong development để phát hiện side effects không tinh khiết (impure render functions). Chỉ xảy ra trong development, không ảnh hưởng production build.
