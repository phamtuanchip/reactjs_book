Hooks Nâng cao

Ngoài useState và useEffect, React còn cung cấp nhiều hook mạnh mẽ hơn. Chương này khám phá useReducer, useContext, useRef, useMemo, useCallback, và cách tự viết Custom Hooks để tái sử dụng logic.

15.1 useReducer — Quản lý state phức tạp

useReducer là thay thế cho useState khi state phức tạp hoặc có nhiều hành động liên quan. Lấy cảm hứng từ Redux.

import { useReducer } from 'react';

// 1. Định nghĩa reducer function
// Reducer nhận (state hiện tại, action) → trả về state mới
function todoReducer(state, action) {
  switch (action.type) {
    case 'ADD':
      return [...state, { id: Date.now(), text: action.payload, done: false }];
    case 'TOGGLE':
      return state.map(t => t.id === action.payload ? { ...t, done: !t.done } : t);
    case 'DELETE':
      return state.filter(t => t.id !== action.payload);
    case 'CLEAR_DONE':
      return state.filter(t => !t.done);
    default:
      throw new Error('Unknown action: ' + action.type);
  }
}

// 2. Dùng useReducer trong component
function TodoApp() {
  const [todos, dispatch] = useReducer(todoReducer, []);

  return (
    <div>
      <button onClick={() => dispatch({ type: 'ADD', payload: 'Học React' })}>
        Thêm
      </button>
      {todos.map(todo => (
        <div key={todo.id}>
          <span onClick={() => dispatch({ type: 'TOGGLE', payload: todo.id })}>
            {todo.text}
          </span>
          <button onClick={() => dispatch({ type: 'DELETE', payload: todo.id })}>
            Xóa
          </button>
        </div>
      ))}
    </div>
  );
}
💡 useState vs useReducer

Dùng useState khi: state đơn giản, ít action. Dùng useReducer khi: state phức tạp, nhiều sub-values liên quan, nhiều action dẫn đến nhiều state transitions, hoặc state tiếp theo phụ thuộc vào state trước đó theo logic phức tạp.

15.2 useContext — Chia sẻ state không cần props drilling

import { createContext, useContext, useState } from 'react';

// 1. Tạo context
const ThemeContext = createContext({
  theme: 'light',
  toggleTheme: () => {}
});

// 2. Provider — bao bọc các component cần dùng context
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');

  const toggleTheme = () => {
    setTheme(prev => prev === 'light' ? 'dark' : 'light');
  };

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// 3. Dùng context trong bất kỳ component con nào
function ThemeToggleButton() {
  const { theme, toggleTheme } = useContext(ThemeContext);
  return (
    <button onClick={toggleTheme}>
      Đang dùng: {theme} — Click để đổi
    </button>
  );
}

// 4. Wrap app với Provider
function App() {
  return (
    <ThemeProvider>
      <Header />
      <Main />
      <Footer />
    </ThemeProvider>
  );
}

// Custom hook để dùng context dễ hơn
function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) throw new Error('useTheme phải dùng trong ThemeProvider');
  return context;
}

15.3 useRef — Tham chiếu không gây re-render

import { useRef, useEffect } from 'react';

// useRef trả về object { current: value }
// Thay đổi ref.current KHÔNG gây re-render!

// 1. Truy cập DOM element
function AutoFocusInput() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus(); // Focus input khi mount
  }, []);

  return <input ref={inputRef} placeholder="Tự động focus" />;
}

// 2. Lưu giá trị persist qua renders mà không gây re-render
function Timer() {
  const [count, setCount] = useState(0);
  const intervalRef = useRef(null); // Lưu interval ID

  const start = () => {
    intervalRef.current = setInterval(() => {
      setCount(prev => prev + 1);
    }, 1000);
  };

  const stop = () => {
    clearInterval(intervalRef.current);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </div>
  );
}

// 3. Lưu giá trị previous
function usePrevious(value) {
  const prevRef = useRef();
  useEffect(() => {
    prevRef.current = value;
  });
  return prevRef.current; // Giá trị render trước
}

// 4. forwardRef — truyền ref từ cha xuống con
import { forwardRef } from 'react';
const MyInput = forwardRef((props, ref) => {
  return <input ref={ref} {...props} />;
});
// Dùng: <MyInput ref={inputRef} />

15.4 useMemo và useCallback — Tối ưu hiệu năng

import { useMemo, useCallback } from 'react';

// useMemo — memoize KẾT QUẢ tính toán tốn kém
function ProductList({ products, searchQuery, sortBy }) {
  // Chỉ tính lại khi products, searchQuery, hoặc sortBy thay đổi
  const filteredAndSorted = useMemo(() => {
    console.log('Đang tính toán...');
    return products
      .filter(p => p.name.toLowerCase().includes(searchQuery.toLowerCase()))
      .sort((a, b) => {
        if (sortBy === 'price') return a.price - b.price;
        return a.name.localeCompare(b.name);
      });
  }, [products, searchQuery, sortBy]);

  return (
    <ul>
      {filteredAndSorted.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}

// useCallback — memoize HÀM để tránh tạo hàm mới mỗi render
function Parent() {
  const [count, setCount] = useState(0);
  const [items, setItems] = useState([]);

  // Hàm này được tạo lại sau mỗi render (kể cả khi count thay đổi)
  // Gây Child re-render dù items không thay đổi!
  const addItem = useCallback((name) => {
    setItems(prev => [...prev, { id: Date.now(), name }]);
  }, []); // Hàm này không cần deps → không bao giờ tạo lại

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+</button>
      <Child onAdd={addItem} /> {/* Không re-render khi count thay đổi */}
    </div>
  );
}

const Child = React.memo(({ onAdd }) => {
  console.log('Child render');
  return <button onClick={() => onAdd('New Item')}>Add</button>;
});
⚠️ Đừng lạm dụng useMemo/useCallback

useMemo và useCallback có chi phí (bộ nhớ, overhead so sánh). Chỉ dùng khi: (1) Tính toán thực sự tốn kém (filter/sort list lớn), (2) Truyền hàm xuống component con được bọc React.memo, (3) Hàm là dependency của useEffect. Đừng "tối ưu sớm"!

15.5 Custom Hooks

Custom Hook là hàm JavaScript bắt đầu bằng use, có thể gọi các hook khác bên trong. Dùng để tái sử dụng logic stateful.

// useFetch — fetch dữ liệu từ API
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;

    async function fetchData() {
      setLoading(true);
      setError(null);
      try {
        const response = await fetch(url);
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const json = await response.json();
        if (!cancelled) setData(json);
      } catch (err) {
        if (!cancelled) setError(err.message);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }

    fetchData();
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading, error };
}

// Dùng:
function UserList() {
  const { data: users, loading, error } = useFetch('/api/users');
  if (loading) return <Spinner />;
  if (error) return <Error message={error} />;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
// useLocalStorage — sync state với localStorage
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const item = localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch {
      return initialValue;
    }
  });

  const setStoredValue = useCallback((newValue) => {
    setValue(newValue);
    localStorage.setItem(key, JSON.stringify(newValue));
  }, [key]);

  return [value, setStoredValue];
}

// Dùng:
const [theme, setTheme] = useLocalStorage('theme', 'dark');

// useDebounce
function useDebounce(value, delay = 300) {
  const [debouncedValue, setDebouncedValue] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debouncedValue;
}

// useWindowSize
function useWindowSize() {
  const [size, setSize] = useState({ width: window.innerWidth, height: window.innerHeight });
  useEffect(() => {
    const handler = () => setSize({ width: window.innerWidth, height: window.innerHeight });
    window.addEventListener('resize', handler);
    return () => window.removeEventListener('resize', handler);
  }, []);
  return size;
}

Câu hỏi ôn bài

1. Khi nào nên dùng useReducer thay vì useState?

  • A. Luôn luôn — useReducer tốt hơn useState
  • B. Khi state phức tạp với nhiều sub-values, hoặc nhiều actions liên quan đến nhau
  • C. Khi state là string hoặc number
  • D. Khi component có nhiều hơn 3 props

Đáp án: B — useReducer phù hợp khi: state phức tạp (object có nhiều trường), nhiều loại update khác nhau (add/toggle/delete/clear), hoặc khi muốn centralize logic update.

2. Sự khác biệt giữa thay đổi ref.current và setState?

  • A. Không có sự khác biệt
  • B. Thay đổi ref.current KHÔNG gây re-render, setState GÂY re-render
  • C. ref.current chỉ dùng cho DOM elements
  • D. setState đồng bộ, ref.current bất đồng bộ

Đáp án: B — Ref là "escape hatch" ra khỏi rendering system. Đổi ref.current = lưu giá trị mà không trigger re-render. Dùng khi cần persist giá trị qua renders nhưng không cần UI cập nhật (interval IDs, timeout IDs, previous values).

3. Quy tắc đặt tên Custom Hook là gì?

  • A. Bắt đầu bằng use (ví dụ: useFetch, useAuth)
  • B. Bắt đầu bằng hook
  • C. Tên phải viết hoa hoàn toàn
  • D. Không có quy tắc đặt tên

Đáp án: A — Custom Hooks bắt buộc bắt đầu bằng use. Lý do: React cần biết đây là hook để kiểm tra "Rules of Hooks" (không gọi trong điều kiện, vòng lặp...). ESLint plugin sẽ cảnh báo nếu vi phạm.

4. useMemo phù hợp nhất cho trường hợp nào?

  • A. Tất cả tính toán trong component
  • B. Tính toán tốn kém mà kết quả phụ thuộc vào dữ liệu ít thay đổi
  • C. Thay thế hoàn toàn useState
  • D. Fetch dữ liệu từ API

Đáp án: B — useMemo cache kết quả tính toán. Phù hợp khi: filter/sort danh sách lớn, tính toán phức tạp, tạo object/array làm dependency của hook khác. Với tính toán đơn giản, overhead của useMemo còn lớn hơn lợi ích.

5. "Props drilling" là vấn đề gì, và Context giải quyết như thế nào?

  • A. Props quá nhiều làm chậm ứng dụng; Context caching props
  • B. Phải truyền props qua nhiều cấp component trung gian không cần dùng; Context cho phép component con đọc trực tiếp từ provider
  • C. Props không thể là function; Context cho phép truyền function
  • D. Props là string, Context là object

Đáp án: B — Props drilling: A → B → C → D → E, trong đó B, C, D chỉ truyền props mà không dùng. Context: Provider bọc ngoài, E đọc trực tiếp qua useContext. Tuy nhiên, đừng dùng Context cho mọi state — chỉ dùng cho dữ liệu "global" thực sự.
