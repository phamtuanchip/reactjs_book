Tối ưu Hiệu năng

React đã tự tối ưu rất tốt, nhưng với ứng dụng phức tạp bạn cần biết cách kiểm soát re-renders, code splitting, và xử lý danh sách lớn. Quan trọng: đừng tối ưu sớm — hãy đo lường trước.

19.2 React.memo

import { memo } from 'react';

// Không dùng memo — re-render mỗi khi parent re-render
function ExpensiveComponent({ data }) {
  console.log('Rendering ExpensiveComponent');
  return <div>{/* UI phức tạp */}</div>;
}

// Với memo — chỉ re-render khi props thực sự thay đổi
const ExpensiveComponent = memo(function({ data }) {
  console.log('Rendering ExpensiveComponent');
  return <div>{/* UI phức tạp */}</div>;
});

// Custom comparison function (khi default shallow compare không đủ)
const OptimizedList = memo(function({ items, selectedId }) {
  return <ul>{items.map(...)}</ul>;
}, (prevProps, nextProps) => {
  // Return true nếu props "bằng nhau" (KHÔNG cần re-render)
  return prevProps.selectedId === nextProps.selectedId
    && prevProps.items.length === nextProps.items.length;
});

// Ví dụ thực tế — Table với sorting/filtering
const DataTable = memo(function DataTable({ data, columns, onSort }) {
  console.log('DataTable render');
  return (
    <table>
      {data.map(row => (
        <tr key={row.id}>
          {columns.map(col => <td key={col.key}>{row[col.key]}</td>)}
        </tr>
      ))}
    </table>
  );
});

// Parent phải dùng useCallback cho onSort!
function App() {
  const [data, setData] = useState([]);
  const [sortKey, setSortKey] = useState('name');

  const handleSort = useCallback((key) => {
    setSortKey(key);
  }, []); // Hàm không đổi → DataTable không re-render

  return <DataTable data={data} onSort={handleSort} />;
}

19.3 Code Splitting với React.lazy và Suspense

Code splitting chia bundle JavaScript thành nhiều chunk nhỏ, chỉ tải khi cần. Giảm thời gian tải lần đầu đáng kể.

import { lazy, Suspense } from 'react';

// Lazy import — component chỉ tải khi được render lần đầu
const HeavyChart = lazy(() => import('./components/HeavyChart'));
const AdminPanel = lazy(() => import('./pages/AdminPanel'));
const RichTextEditor = lazy(() => import('./components/RichTextEditor'));

// Suspense — hiển thị fallback trong khi tải
function App() {
  return (
    <Suspense fallback={<div className="spinner">Đang tải...</div>}>
      <HeavyChart data={chartData} />
    </Suspense>
  );
}

// Route-based code splitting — phổ biến nhất
import { Routes, Route } from 'react-router-dom';

const Home = lazy(() => import('./pages/Home'));
const Products = lazy(() => import('./pages/Products'));
const Dashboard = lazy(() => import('./pages/Dashboard'));

function App() {
  return (
    <Suspense fallback={<PageLoader />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/products" element={<Products />} />
        <Route path="/dashboard" element={<Dashboard />} />
      </Routes>
    </Suspense>
  );
}

// Dashboard.[hash].js  ← tải khi vào trang Dashboard

19.4 Virtualization — Render danh sách lớn

Render 10,000 DOM nodes cùng lúc → cực chậm. Virtualization chỉ render các phần tử đang hiển thị trong viewport.

npm install @tanstack/react-virtual
# hoặc: npm install react-window react-virtualized
// react-window — đơn giản nhất
import { FixedSizeList, VariableSizeList } from 'react-window';

function VirtualizedList({ items }) {
  const Row = ({ index, style }) => (
    <div style={style}> {/* style chứa vị trí/kích thước — BẮT BUỘC */}
      {items[index].name}
    </div>
  );

  return (
    <FixedSizeList
      height={600}          // Chiều cao container
      itemCount={items.length}
      itemSize={50}          // Chiều cao mỗi row (fixed)
      width="100%"
    >
      {Row}
    </FixedSizeList>
  );
}

// @tanstack/react-virtual — flexible hơn
import { useVirtualizer } from '@tanstack/react-virtual';

function VirtualTable({ rows }) {
  const parentRef = useRef(null);

  const rowVirtualizer = useVirtualizer({
    count: rows.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50, // estimated row height
    overscan: 10,            // render thêm 10 rows ngoài viewport
  });

  return (
    <div ref={parentRef} style={{ height: '600px', overflow: 'auto' }}>
      <div style={{ height: rowVirtualizer.getTotalSize() + 'px', position: 'relative' }}>
        {rowVirtualizer.getVirtualItems().map(virtualRow => (
          <div
            key={virtualRow.index}
            style={{
              position: 'absolute',
              top: 0,
              left: 0,
              width: '100%',
              height: virtualRow.size + 'px',
              transform: `translateY(${virtualRow.start}px)`,
            }}
          >
            {rows[virtualRow.index].name}
          </div>
        ))}
      </div>
    </div>
  );
}

19.6 Các tối ưu khác

// 1. Tránh inline object/array trong JSX (tạo object mới mỗi render)
// Sai:
<Component style={{ color: 'red' }} data={[1,2,3]} />
// Đúng:
const style = { color: 'red' };
const data = [1, 2, 3];
<Component style={style} data={data} />
// Hoặc dùng useMemo nếu phụ thuộc state

// 2. Key trong danh sách — dùng ID, không dùng index
// Sai: items.map((item, index) => <Item key={index} />)
// Đúng: items.map(item => <Item key={item.id} />)

// 3. Tránh anonymous component trong render
// Sai: {showModal && <Modal><div>...</div></Modal>}
// Đúng: hoist component ra ngoài render function

// 4. Image optimization
<img
  src="photo.jpg"
  loading="lazy"     // Lazy load khi vào viewport
  decoding="async"   // Decode ảnh bất đồng bộ
  fetchpriority="high" // Cho hero image
/>

// 5. Debounce expensive operations
const debouncedSearch = useCallback(
  debounce((query) => fetchResults(query), 300),
  []
);

// 6. Web Workers cho tính toán nặng
const worker = new Worker('./heavy-computation.js');
worker.onmessage = (e) => setResult(e.data);
worker.postMessage(data); // Gửi data để tính toán

Câu hỏi ôn bài

1. React.memo so sánh props như thế nào để quyết định có re-render không?

  • A. So sánh sâu (deep comparison) toàn bộ object
  • B. Shallow comparison — so sánh tham chiếu cho objects/arrays
  • C. Không so sánh, luôn re-render
  • D. Serialize thành JSON rồi so sánh string

Đáp án: B — React.memo dùng shallow comparison: primitive values so sánh bằng giá trị, objects/arrays so sánh bằng tham chiếu. Vì vậy cần kết hợp useCallback (cho functions) và useMemo (cho objects/arrays).

2. Virtualization giải quyết vấn đề gì?

  • A. Tải dữ liệu nhanh hơn từ server
  • B. Chỉ render các DOM nodes đang hiển thị trong viewport, giữ DOM nhỏ dù danh sách rất lớn
  • C. Cache dữ liệu trong bộ nhớ
  • D. Tối ưu CSS animations

Đáp án: B — Với 10,000 items: render tất cả → 10,000 DOM nodes → chậm. Virtualization: chỉ render ~20 items đang hiển thị → DOM chỉ có 20 nodes → nhanh. Khi scroll → thay đổi items hiển thị.

3. Tại sao dùng index làm key trong danh sách có thể gây bug?

  • A. index không hợp lệ làm key
  • B. Khi danh sách thêm/xóa/sắp xếp lại, index không còn là định danh ổn định — React update sai component
  • C. index quá lớn gây tràn bộ nhớ
  • D. Không có bug, index hoạt động tốt

Đáp án: B — Ví dụ: items=[A,B,C], keys=[0,1,2]. Xóa A → items=[B,C], keys=[0,1]. React nghĩ key=0 vẫn là item đầu (nhưng giờ là B) → update sai. Dùng ID ổn định từ data.

4. Code splitting (lazy loading) cải thiện điều gì?

  • A. Runtime performance sau khi load
  • B. Initial load time — tải ít JavaScript hơn lần đầu, phần còn lại tải khi cần
  • C. Memory usage
  • D. API response time

Đáp án: B — Không có code splitting: tải 5MB JS ngay từ đầu dù user chỉ xem trang Home. Với code splitting: tải 500KB (common + Home), tải thêm khi navigate đến trang khác.

5. Nguyên tắc "Don't optimize prematurely" có nghĩa là gì?

  • A. Không bao giờ tối ưu hiệu năng
  • B. Chỉ tối ưu khi đo lường và xác định được vấn đề thực sự (không đoán mò)
  • C. Tối ưu chỉ khi production
  • D. Dùng useMemo và useCallback ở mọi nơi

Đáp án: B — Donald Knuth: "Premature optimization is the root of all evil". Thêm useMemo/useCallback ở mọi nơi thực sự làm code chậm hơn (overhead). Quy trình đúng: (1) Đo lường bằng Profiler, (2) Xác định bottleneck, (3) Tối ưu đúng chỗ.
