Làm quen với Web và Lập trình

Trước khi viết một dòng code, hãy cùng hiểu Internet và Web thực sự hoạt động như thế nào. Đây là nền tảng tư duy mà mọi lập trình viên web đều cần có.

1.1 Web là gì? Lịch sử ngắn gọn của Internet

Khi bạn mở trình duyệt và gõ google.com, trong vòng chưa đến một giây bạn nhận được kết quả. Điều kỳ diệu đó xảy ra như thế nào? Để hiểu được, chúng ta cần biết Web là gì và nó ra đời từ đâu.

Internet và World Wide Web — Hai thứ khác nhau

Nhiều người nhầm lẫn Internet và Web (World Wide Web) là một. Thực ra:

  • Internet là hạ tầng vật lý: hàng triệu máy tính, cáp quang, bộ định tuyến (router) kết nối với nhau trên toàn thế giới. Internet là "con đường cao tốc".
  • World Wide Web (Web) là một dịch vụ chạy trên Internet. Web là hệ thống các trang tài liệu (trang web) liên kết với nhau qua các đường dẫn (hyperlink). Web là "những chiếc xe" chạy trên con đường đó.

Ngoài Web, Internet còn chứa nhiều dịch vụ khác: Email (SMTP/IMAP), truyền file (FTP), nhắn tin tức thời, streaming video, v.v.

Lịch sử hình thành

  • 1969 — ARPANET: Tiền thân của Internet, được Bộ Quốc phòng Mỹ tạo ra để kết nối các trường đại học và cơ quan nghiên cứu. Ban đầu chỉ có 4 nút mạng.
  • 1983 — TCP/IP: Bộ giao thức chuẩn TCP/IP được thống nhất, đặt nền móng kỹ thuật cho Internet hiện đại.
  • 1991 — World Wide Web ra đời: Tim Berners-Lee, nhà khoa học tại CERN (Thụy Sĩ), phát minh ra Web. Ông tạo ra ba thứ: ngôn ngữ HTML để viết trang web, giao thức HTTP để truyền tải, và URL để định vị tài nguyên.
  • 1993 — Mosaic: Trình duyệt đồ họa đầu tiên ra đời, giúp Web trở nên phổ biến với đại chúng vì có thể hiển thị hình ảnh.
  • 1995–2000 — Dot-com Boom: Hàng nghìn công ty Internet ra đời. Amazon, Google, eBay xuất hiện trong giai đoạn này.
  • 2004 — Web 2.0: Người dùng bắt đầu tạo nội dung (blog, mạng xã hội). Facebook ra đời 2004, YouTube 2005, Twitter 2006.
  • 2008 trở đi — Kỷ nguyên di động: Smartphone bùng nổ, Web phải thích ứng với màn hình nhỏ. Responsive Design trở thành bắt buộc.
  • 2010 trở đi — Web App: Web không chỉ là trang đọc nữa mà là ứng dụng đầy đủ chức năng: Google Docs, Figma, Notion... đều chạy trên trình duyệt.
💡 Ghi chú

Tim Berners-Lee không nhận bằng sáng chế cho phát minh Web của mình. Ông muốn Web là tài sản của toàn nhân loại, miễn phí và mở cho tất cả. Quyết định này đã thay đổi thế giới.

1.2 Client và Server — Sự phân chia hai phía của ứng dụng web

Mọi tương tác trên Web đều dựa trên mô hình Client–Server. Đây là khái niệm cốt lõi mà bạn sẽ dùng hàng ngày khi lập trình web.

Client là gì?

Client (hay "phía khách") là phần mềm hoặc thiết bị gửi yêu cầu đến server để lấy dữ liệu hoặc thực hiện hành động. Thường gặp nhất là trình duyệt web (Chrome, Firefox, Safari, Edge). Ngoài ra, ứng dụng mobile, ứng dụng desktop, hay thậm chí script tự động cũng có thể là client.

Server là gì?

Server (hay "phía máy chủ") là máy tính (hoặc chương trình) luôn bật, lắng nghe các yêu cầu từ client, xử lý và trả về kết quả. Server thường nằm trong các trung tâm dữ liệu (data center) với phần cứng mạnh mẽ và kết nối mạng tốc độ cao.

Giao tiếp qua HTTP

Client và Server giao tiếp với nhau qua giao thức HTTP (HyperText Transfer Protocol) hoặc phiên bản bảo mật hơn là HTTPS (HTTP Secure). Mỗi lần giao tiếp gồm hai bước:

  1. HTTP Request: Client gửi yêu cầu lên Server, nói rõ muốn làm gì (lấy trang, gửi form, xóa dữ liệu...)
  2. HTTP Response: Server xử lý và gửi lại kết quả (HTML, JSON, hình ảnh, lỗi...)

Các phương thức HTTP phổ biến

HTTP Request có nhiều "phương thức" (method) khác nhau, mỗi cái có ý nghĩa riêng:

  • GET: Lấy dữ liệu. Ví dụ: tải trang web, lấy danh sách sản phẩm.
  • POST: Gửi dữ liệu mới lên server. Ví dụ: đăng ký tài khoản, đăng bài viết.
  • PUT / PATCH: Cập nhật dữ liệu đã có. PUT thay toàn bộ, PATCH thay một phần.
  • DELETE: Xóa dữ liệu.

HTTP Status Code — Mã trạng thái

Server trả về mã số cho biết kết quả của request:

  • 2xx — Thành công: 200 OK, 201 Created, 204 No Content
  • 3xx — Chuyển hướng: 301 Moved Permanently, 302 Found
  • 4xx — Lỗi từ phía Client: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
  • 5xx — Lỗi từ phía Server: 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

1.3 Trình duyệt làm gì khi bạn gõ một URL?

Bạn gõ https://www.google.com và nhấn Enter. Điều gì xảy ra trong vòng chưa đến 1 giây đó? Đây là một trong những câu hỏi phỏng vấn kinh điển nhất trong ngành lập trình web.

Bước 1: Phân tích URL

Trình duyệt phân tích URL thành các thành phần:

https://www.google.com/search?q=reactjs#results
│       │               │       │         │
│       │               │       │         └─ Fragment (cuộn đến phần #results)
│       │               │       └─ Query string (tham số tìm kiếm)
│       │               └─ Path (đường dẫn đến tài nguyên)
│       └─ Domain (tên miền)
└─ Protocol (giao thức: https)

Bước 2: DNS Lookup — Tra cứu địa chỉ IP

Máy tính không hiểu tên miền như google.com. Nó cần địa chỉ IP (như 142.250.185.46). DNS (Domain Name System) là "quyển danh bạ điện thoại" của Internet, chuyển đổi tên miền thành địa chỉ IP.

Trình tự tra cứu DNS (từ nhanh đến chậm):

  1. Browser cache: Trình duyệt nhớ các DNS đã tra cứu gần đây.
  2. OS cache: Hệ điều hành cũng có bộ nhớ đệm DNS (file hosts).
  3. Router cache: Bộ định tuyến gia đình cũng cache DNS.
  4. DNS Resolver của ISP: Nhà cung cấp Internet của bạn có server DNS riêng.
  5. Root DNS → TLD DNS → Authoritative DNS: Nếu không ai biết, hỏi từ gốc lên.

Bước 3: Thiết lập kết nối TCP

Sau khi có IP, trình duyệt thiết lập kết nối với server qua giao thức TCP bằng quy trình Three-Way Handshake:

sequenceDiagram participant B as 🖥️ Trình duyệt participant D as 🗂️ DNS Server participant S as 🌐 Web Server B->>D: Tôi cần IP của google.com? D-->>B: IP là 142.250.x.x B->>S: SYN — Tôi muốn kết nối S-->>B: SYN-ACK — OK, sẵn sàng B->>S: ACK — Đã nhận xác nhận Note over B,S: Kết nối TCP thiết lập ✅ B->>S: GET /index.html HTTP/1.1 S-->>B: 200 OK + HTML + CSS + JS

Nếu dùng HTTPS, sau TCP handshake còn có thêm TLS Handshake để mã hóa kết nối — bảo đảm dữ liệu không bị nghe lén.

Bước 4: Gửi HTTP Request

GET / HTTP/1.1
Host: www.google.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Accept-Language: vi-VN,vi;q=0.9,en-US;q=0.8
Accept-Encoding: gzip, deflate, br
Connection: keep-alive

<!DOCTYPE html>
<html lang="vi">

Bước 6: Trình duyệt phân tích và hiển thị

Đây là bước phức tạp nhất. Trình duyệt thực hiện quy trình Critical Rendering Path:

  1. Parse HTML → DOM Tree: Đọc HTML, tạo cây đối tượng Document Object Model.
  2. Parse CSS → CSSOM Tree: Đọc CSS, tạo CSS Object Model.
  3. JavaScript Execution: Chạy các file JS (có thể thay đổi DOM và CSSOM).
  4. Render Tree: Kết hợp DOM + CSSOM tạo Render Tree (chỉ chứa các phần tử hiển thị).
  5. Layout (Reflow): Tính toán vị trí và kích thước của từng phần tử.
  6. Paint: Vẽ các pixels lên màn hình.
  7. Compositing: Ghép các layer lại thành hình ảnh cuối cùng.
💡 Tại sao điều này quan trọng?

Hiểu quy trình rendering giúp bạn tối ưu hiệu năng web. Ví dụ: đặt CSS ở <head> (không block rendering), đặt JS cuối <body> hoặc dùng defer (không block HTML parsing). Chúng ta sẽ đi sâu vào tối ưu ở các chương sau.

1.4 Các loại ứng dụng web

Không phải website nào cũng giống nhau. Có nhiều kiến trúc khác nhau, mỗi loại phù hợp với nhu cầu riêng. Hiểu sự khác biệt này giúp bạn chọn đúng công nghệ khi xây dựng sản phẩm.

1. Static Site (Trang tĩnh)

Server chỉ phục vụ các file HTML, CSS, JS đã được tạo sẵn. Không có xử lý phía server, không có database.

  • Ưu điểm: Cực nhanh, bảo mật cao, chi phí hosting rẻ (thậm chí miễn phí với GitHub Pages, Netlify).
  • Nhược điểm: Nội dung cố định, không cá nhân hóa được.
  • Ví dụ thực tế: Blog cá nhân, landing page, tài liệu kỹ thuật, portfolio.
  • Công cụ phổ biến: Hugo, Jekyll, Gatsby, Eleventy.

2. Dynamic Site (Trang động)

Server tạo ra HTML "on the fly" dựa trên yêu cầu của người dùng và dữ liệu từ database.

  • Ưu điểm: Nội dung thay đổi theo người dùng, dữ liệu thời gian thực.
  • Nhược điểm: Chậm hơn (cần xử lý mỗi request), tốn kém hơn.
  • Ví dụ thực tế: Các trang web truyền thống viết bằng PHP (WordPress), Ruby on Rails.
  • Luồng hoạt động: Request → Server xử lý → Truy vấn DB → Tạo HTML → Trả về client.

3. SPA — Single Page Application

Trình duyệt tải về một file HTML duy nhất và ứng dụng chạy hoàn toàn ở phía client. Khi điều hướng giữa các trang, JavaScript thay đổi nội dung mà không cần tải lại trang.

  • Ưu điểm: Trải nghiệm người dùng mượt mà như app native, sau lần tải đầu rất nhanh.
  • Nhược điểm: SEO khó hơn, lần tải đầu tiên chậm, cần JavaScript bật.
  • Ví dụ thực tế: Gmail, Google Maps, Facebook, Twitter (X), Notion.
  • Công cụ phổ biến: React, Vue.js, Angular — đây là lý do React quan trọng!

4. SSR — Server-Side Rendering

Kết hợp ưu điểm của Dynamic Site và SPA. Server render HTML đầy đủ cho mỗi request, nhưng sau đó JavaScript "tiếp quản" và làm ứng dụng hoạt động như SPA (quá trình này gọi là hydration).

  • Ưu điểm: SEO tốt (search engine thấy nội dung đầy đủ), tải trang đầu nhanh.
  • Nhược điểm: Phức tạp hơn, tốn tài nguyên server hơn.
  • Ví dụ thực tế: Các trang thương mại điện tử, tin tức.
  • Công cụ phổ biến: Next.js (với React), Nuxt.js (với Vue), SvelteKit.

5. PWA — Progressive Web App

Web app có khả năng hoạt động như app mobile native. Người dùng có thể "cài đặt" lên màn hình chính điện thoại và dùng offline.

  • Công nghệ cốt lõi: Service Worker (chạy nền, cache tài nguyên), Web App Manifest (metadata để cài lên màn hình chính).
  • Ví dụ thực tế: Twitter Lite, Starbucks app, Uber Lite.
  • Ưu điểm: Không cần lên App Store, tự cập nhật, nhẹ hơn app native nhiều.

1.5 Công cụ cần thiết để học ReactJS

Lập trình cần công cụ tốt. Đây là bộ công cụ chuẩn mà hầu hết lập trình viên React sử dụng.

VS Code — Trình soạn thảo code

Visual Studio Code (VS Code) là trình soạn thảo code miễn phí, mã nguồn mở của Microsoft. Nó hiện là editor phổ biến nhất thế giới (theo khảo sát Stack Overflow 2023, hơn 73% lập trình viên dùng VS Code).

Tải về tại: https://code.visualstudio.com

Extensions cần cài ngay:

1. ESLint

Phân tích code JavaScript/React của bạn và cảnh báo các lỗi tiềm ẩn hoặc vi phạm coding style ngay khi bạn gõ. Giống như "người kiểm tra chính tả" cho code.

// Ví dụ lỗi ESLint bắt được:
const name = "Alice"   // ✗ Missing semicolon
let unused = 42        // ✗'unused' is assigned but never used

const name = "Alice";  // ✓ Correct

2. Prettier — Code Formatter

Tự động format code của bạn theo chuẩn thống nhất. Không cần tốn thời gian tranh luận về tab vs space — Prettier quyết định tất cả.

// Trước khi format (bạn gõ tùy tiện):
const obj={name:'Alice',age:30,city:'HCM'}

// Sau khi Prettier format (tự động):
const obj = {
  name: "Alice",
  age: 30,
  city: "HCM",
};

3. ES7+ React/Redux/React-Native Snippets

Cung cấp hàng chục "snippet" (đoạn code mẫu) cho React. Gõ vài ký tự và nhấn Tab, VS Code tự điền code đầy đủ.

// Gõ "rafce" + Tab sẽ tự tạo:
import React from 'react';

const ComponentName = () => {
  return (
    <div>ComponentName</div>
  );
};

export default ComponentName;

4. GitLens

Hiển thị thông tin git (ai sửa dòng này, khi nào, commit message gì) ngay trong editor.

5. Auto Rename Tag

Khi đổi tên thẻ mở, thẻ đóng tự động đổi theo. Rất tiện khi làm việc với JSX.

Node.js — JavaScript Runtime

Node.js cho phép chạy JavaScript bên ngoài trình duyệt (trực tiếp trên máy tính). Đây là nền tảng để chạy các công cụ lập trình như npm, Vite, Webpack.

Tải về tại: https://nodejs.org — Luôn chọn phiên bản LTS (Long Term Support) để đảm bảo ổn định.

# Kiểm tra đã cài thành công
node --version   # In ra: v20.x.x
npm --version    # In ra: 10.x.x

npm (Node Package Manager) được cài kèm với Node.js. npm là kho chứa hàng triệu thư viện mã nguồn mở — bạn có thể thêm bất kỳ tính năng nào vào dự án chỉ bằng một lệnh.

# Cài thư viện lodash
npm install lodash

# Cài và lưu vào devDependencies (chỉ dùng khi dev)
npm install --save-dev eslint

Chrome DevTools — Công cụ phát triển của trình duyệt

Chrome DevTools là bộ công cụ gỡ lỗi và phân tích tích hợp sẵn trong Chrome. Đây là người bạn tốt nhất của lập trình viên web.

Mở DevTools bằng:

  • Nhấn F12
  • Hoặc Ctrl+Shift+I (Windows/Linux), Cmd+Option+I (Mac)
  • Hoặc chuột phải vào trang → "Inspect" (Kiểm tra)

1.6 Khám phá Chrome DevTools

Tab Elements (Phần tử)

Hiển thị cấu trúc HTML của trang và CSS đang áp dụng. Bạn có thể:

  • Click vào bất kỳ phần tử HTML nào để xem CSS của nó
  • Chỉnh sửa HTML/CSS trực tiếp trong DevTools để xem kết quả ngay (thay đổi không được lưu)
  • Dùng biểu tượng "mũi tên" ở góc trái để click vào phần tử trên trang và highlight nó trong DOM
/* Trong tab Elements, bạn sẽ thấy CSS như: */
element.style {
  color: red;
}

h1 {
  font-size: 2rem;  /* Computed: 32px */
  font-weight: 700;
}

Tab Console (Bảng điều khiển)

Nơi hiển thị các thông báo log từ JavaScript và cho phép bạn chạy code JS trực tiếp.

// Bạn có thể gõ trực tiếp trong Console:
console.log("Xin chào thế giới!");   // In ra log thường
console.warn("Cảnh báo!");           // In ra màu vàng
console.error("Lỗi rồi!");          // In ra màu đỏ
console.table([{name: "Alice"}, {name: "Bob"}]); // In dạng bảng

// Thậm chí chạy code phức tạp:
document.title = "Tôi đã đổi tên trang!";
document.body.style.background = "lightblue";

Tab Network (Mạng)

Hiển thị tất cả các request mạng mà trang web thực hiện. Đây là tab bạn dùng nhiều nhất khi debug API.

Thông tin quan trọng trong tab Network:

  • Name: Tên file hoặc URL của request
  • Status: Mã trạng thái HTTP (200, 404, 500...)
  • Type: Loại tài nguyên (document, stylesheet, script, xhr, fetch, img...)
  • Size: Dung lượng file
  • Time: Thời gian tải
  • Waterfall: Biểu đồ thời gian, cho thấy request nào làm chậm trang

Tab Sources (Nguồn)

Cho phép bạn xem và debug code JavaScript với debugger đầy đủ: đặt breakpoint, xem giá trị biến, thực thi từng dòng.

// Trong code JS, thêm dòng này để dừng thực thi tại đó:
debugger;

// Hoặc đặt breakpoint trong tab Sources bằng cách
// click vào số dòng bên trái

Tab Performance và Lighthouse

Performance: Ghi lại và phân tích hiệu năng trang web: FPS, rendering, scripting, layout.
Lighthouse: Tự động kiểm tra và cho điểm trang web về Performance, Accessibility, SEO, Best Practices.

💡 Mẹo DevTools

Nhấn Ctrl+Shift+P trong DevTools để mở Command Palette — giống VS Code. Bạn có thể tìm nhanh bất kỳ tính năng nào của DevTools. Thử gõ "dark mode" để bật giao diện tối cho DevTools!

Bài tập thực hành

Bài tập 1.1: Khám phá Network Tab

  1. Mở Chrome và truy cập https://www.youtube.com
  2. Mở DevTools (F12) và chuyển sang tab Network
  3. Reload lại trang (F5)
  4. Quan sát và ghi lại:
    • Có bao nhiêu request được thực hiện?
    • Request đầu tiên (document) có status code gì?
    • Có những loại tài nguyên nào được tải (JS, CSS, Image, XHR...)?
    • Tổng dung lượng trang là bao nhiêu?
    • Tổng thời gian tải là bao nhiêu giây?
  5. Lọc chỉ xem request loại XHR/Fetch — đây là các API call của YouTube để lấy dữ liệu video. Click vào một request, xem tab Response để thấy dữ liệu JSON trả về.

Bài tập 1.2: Thực hành Console

Mở Console của DevTools và thử các lệnh sau:

// Thay đổi title của trang
document.title = "Tôi đã học DevTools!"

// Đếm số lượng thẻ img trên trang
document.querySelectorAll("img").length

// Lấy URL hiện tại
window.location.href

// Thay đổi màu nền trang
document.body.style.backgroundColor = "#1a1a2e"

Bài tập 1.3: Tìm tài nguyên ẩn

Truy cập bất kỳ trang web nào bạn yêu thích. Dùng tab Elements để:

  1. Tìm và đọc toàn bộ nội dung meta description của trang (thẻ <meta name="description">)
  2. Tìm màu chính (primary color) mà trang web sử dụng bằng cách inspect phần tử nổi bật nhất
  3. Thử thay đổi nội dung text của một đoạn văn bản trên trang (click đôi vào text trong Elements)

Câu hỏi ôn bài

1. Sự khác biệt cơ bản giữa Internet và World Wide Web là gì?

  • A. Đây là hai cách gọi khác nhau của cùng một thứ
  • B. Internet là hạ tầng mạng vật lý, còn Web là một dịch vụ chạy trên Internet
  • C. Web ra đời trước Internet
  • D. Internet chỉ dành cho máy tính, Web dành cho điện thoại

Đáp án: B — Internet là "con đường cao tốc" (hạ tầng vật lý), còn Web là một trong nhiều "xe" chạy trên đó.

2. Khi trình duyệt gửi request GET /products HTTP/1.1 đến server và nhận được response có status code 404, điều đó có nghĩa là?

  • A. Server gặp lỗi nội bộ
  • B. Yêu cầu thành công và dữ liệu đã được trả về
  • C. Tài nguyên được yêu cầu không tồn tại trên server
  • D. Client chưa được xác thực

Đáp án: C — 404 Not Found có nghĩa là server không tìm thấy tài nguyên mà client yêu cầu tại đường dẫn đó.

3. Loại ứng dụng web nào phù hợp nhất khi bạn muốn SEO tốt VÀ trải nghiệm người dùng mượt mà như app mobile?

  • A. Static Site
  • B. SPA (Single Page Application)
  • C. SSR (Server-Side Rendering)
  • D. PWA (Progressive Web App)

Đáp án: C — SSR kết hợp ưu điểm của cả hai: HTML đầy đủ cho SEO (search engine crawl được) và JavaScript tiếp quản sau đó để tạo UX mượt mà.

4. Trong Chrome DevTools, bạn muốn xem dữ liệu JSON mà một API trả về khi trang load. Bạn nên dùng tab nào?

  • A. Elements
  • B. Console
  • C. Network
  • D. Sources

Đáp án: C — Tab Network hiển thị tất cả các request mạng bao gồm API calls. Bạn có thể click vào từng request để xem Response headers và body.

5. DNS (Domain Name System) có chức năng chính là?

  • A. Mã hóa kết nối giữa trình duyệt và server
  • B. Chuyển đổi tên miền (như google.com) thành địa chỉ IP
  • C. Lưu trữ file HTML trên server
  • D. Kiểm soát băng thông mạng

Đáp án: B — DNS là "quyển danh bạ" của Internet, giúp máy tính tìm địa chỉ IP tương ứng với tên miền để có thể kết nối.
