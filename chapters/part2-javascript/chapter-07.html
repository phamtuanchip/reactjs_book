Lập trình Bất đồng bộ (Async)

JavaScript chạy trên một luồng duy nhất — nhưng điều đó không có nghĩa là nó bị "đứng hình" khi chờ dữ liệu. Trong chương này, bạn sẽ hiểu tại sao bất đồng bộ là linh hồn của JavaScript hiện đại, từ callback truyền thống đến Promise thanh lịch và async/await dễ đọc như code đồng bộ.

1. Tại sao JavaScript cần bất đồng bộ?

Hãy tưởng tượng bạn đang viết code để lấy dữ liệu người dùng từ một server ở nước ngoài. Nếu JavaScript phải chờ đợi câu trả lời về trước khi làm bất kỳ việc gì khác, trang web của bạn sẽ bị đóng băng trong vài giây — không ai click được, không gõ được, giao diện chết cứng. Đó chính là vấn đề của lập trình đồng bộ (synchronous) khi làm việc với các tác vụ chậm.

Trong thực tế, có rất nhiều tác vụ cần thời gian:

  • Gọi API — lấy danh sách sản phẩm, thông tin người dùng từ server
  • Đọc/ghi file — trong môi trường Node.js
  • Truy vấn database — chờ kết quả truy vấn SQL
  • Timer — setTimeout, setInterval
  • User input — chờ người dùng nhấn nút, điền form
  • Geolocation — xác định vị trí người dùng
💡 Quy tắc vàng

Bất kỳ tác vụ nào cần chờ kết quả từ bên ngoài (network, disk, timer) đều là bất đồng bộ. JavaScript xử lý chúng mà không block luồng chính, giúp giao diện luôn mượt mà.

3. Event Loop — Trái tim của JavaScript Async

JavaScript là ngôn ngữ single-threaded — chỉ có một luồng thực thi. Vậy làm sao nó xử lý được nhiều việc cùng lúc? Câu trả lời là Event Loop.

Các thành phần chính

  • Call Stack — Nơi code JavaScript đang thực thi. Khi gọi một hàm, nó được đẩy vào stack. Khi hàm kết thúc, nó được lấy ra.
  • Web APIs — Được cung cấp bởi trình duyệt (không phải JS engine): setTimeout, fetch, DOM events, v.v. Khi bạn gọi những API này, trình duyệt xử lý chúng ở background.
  • Callback Queue (Macrotask Queue) — Hàng đợi chứa các callback từ setTimeout, setInterval, DOM events khi chúng hoàn thành.
  • Microtask Queue — Ưu tiên cao hơn Callback Queue. Chứa callback từ Promise.then(), queueMicrotask(), MutationObserver.
  • Event Loop — Vòng lặp liên tục kiểm tra: Call Stack rỗng chưa? Nếu rỗng, lấy task từ queue (Microtask trước, rồi Macrotask) và đẩy vào Stack.

4. setTimeout và setInterval

setTimeout — chạy một lần sau khoảng thời gian
// Cú pháp: setTimeout(callback, milliseconds, ...args)
const timerId = setTimeout(() => {
  console.log('Chạy sau 2 giây!');
}, 2000);

// Hủy timer trước khi chạy
clearTimeout(timerId);

// Truyền tham số
setTimeout((name, age) => {
  console.log(`Xin chào ${name}, ${age} tuổi`);
}, 1000, 'Minh', 25);
// Output sau 1 giây: "Xin chào Minh, 25 tuổi"
setInterval — lặp đi lặp lại
let count = 0;
const intervalId = setInterval(() => {
  count++;
  console.log(`Đã chạy ${count} lần`);

  if (count >= 5) {
    clearInterval(intervalId); // Dừng sau 5 lần
    console.log('Đã dừng!');
  }
}, 1000); // Chạy mỗi 1 giây

// Ứng dụng thực tế: đồng hồ đếm ngược
function countdown(seconds) {
  let remaining = seconds;
  const id = setInterval(() => {
    console.log(`Còn ${remaining} giây...`);
    remaining--;
    if (remaining < 0) {
      clearInterval(id);
      console.log('🚀 Phóng!');
    }
  }, 1000);
}

countdown(5); // Đếm ngược từ 5

5. Callback Pattern và Callback Hell

Cách đầu tiên JavaScript giải quyết bất đồng bộ là callback — truyền một hàm vào như tham số để gọi khi tác vụ hoàn thành.

Callback cơ bản
// Mô phỏng lấy dữ liệu từ server (delay 1 giây)
function getUserFromServer(userId, callback) {
  setTimeout(() => {
    const user = { id: userId, name: 'Nguyễn Văn An', email: 'an@example.com' };
    callback(null, user); // Node.js convention: (error, result)
  }, 1000);
}

getUserFromServer(1, (error, user) => {
  if (error) {
    console.error('Lỗi:', error);
    return;
  }
  console.log('Người dùng:', user);
});

Callback Hell — Pyramid of Doom

Vấn đề xuất hiện khi bạn cần thực hiện nhiều tác vụ bất đồng bộ nối tiếp nhau. Code trở thành một "kim tự tháp" lồng nhau, rất khó đọc và debug:

❌ Callback Hell — Code thực tế khó đọc
getUserFromServer(1, (err, user) => {
  if (err) return handleError(err);

  getOrdersByUser(user.id, (err, orders) => {
    if (err) return handleError(err);

    getProductDetails(orders[0].productId, (err, product) => {
      if (err) return handleError(err);

      getInventory(product.id, (err, inventory) => {
        if (err) return handleError(err);

        updateStock(inventory.id, inventory.count - 1, (err, result) => {
          if (err) return handleError(err);

          console.log('Xong! Stock đã được cập nhật:', result);
          // → Pyramid of doom: code lún sâu theo từng bước
        });
      });
    });
  });
});
🔥 Vấn đề của Callback Hell

1. Khó đọc — cần phải theo dõi nhiều cấp lồng nhau
2. Khó debug — stack trace rối rắm
3. Khó xử lý lỗi — phải check error ở mỗi cấp
4. Khó tái sử dụng — logic bị chôn vùi trong các closure lồng nhau

6. Promise — Giải pháp hiện đại

Promise được giới thiệu trong ES6 (2015) để giải quyết vấn đề callback hell. Một Promise đại diện cho một giá trị chưa có sẵn, nhưng sẽ có trong tương lai (hoặc thất bại).

Ba trạng thái của Promise

stateDiagram-v2 [*] --> Pending : new Promise() Pending --> Fulfilled : resolve(value) Pending --> Rejected : reject(error) Fulfilled --> [*] : .then(handler) Rejected --> [*] : .catch(handler) Rejected --> Fulfilled : .catch() returns value Fulfilled --> Pending : .then() returns new Promise note right of Pending Đang chờ kết quả async operation end note note right of Fulfilled Thành công! Có dữ liệu trả về end note note right of Rejected Thất bại error object end note
Tạo và sử dụng Promise
// Tạo Promise
const myPromise = new Promise((resolve, reject) => {
  // Executor function chạy ngay lập tức
  const success = true;

  if (success) {
    resolve({ data: 'Dữ liệu thành công!' }); // ← Fulfilled
  } else {
    reject(new Error('Có lỗi xảy ra!'));    // ← Rejected
  }
});

// Sử dụng Promise: .then() .catch() .finally()
myPromise
  .then(result => {
    console.log('Thành công:', result.data);
    return result.data.toUpperCase(); // Giá trị return sẽ là input của .then() tiếp theo
  })
  .then(upperData => {
    console.log('Uppercase:', upperData);
  })
  .catch(error => {
    console.error('Lỗi:', error.message); // Bắt lỗi từ bất kỳ .then() nào ở trên
  })
  .finally(() => {
    console.log('Luôn chạy dù thành công hay thất bại');
  });

Promise Chaining — Tránh Callback Hell

✅ Promise Chain — Dễ đọc hơn nhiều
function getUser(id) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ id, name: 'An' }), 500);
  });
}

function getOrders(user) {
  return new Promise((resolve) => {
    setTimeout(() => resolve([{ id: 1, product: 'Laptop', userId: user.id }]), 500);
  });
}

function getProduct(order) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ name: order.product, price: 1500 }), 500);
  });
}

// ✅ Flat chain — không có "pyramid of doom"
getUser(1)
  .then(user => getOrders(user))
  .then(orders => getProduct(orders[0]))
  .then(product => console.log('Sản phẩm:', product.name, '-', product.price, 'USD'))
  .catch(error => console.error('Lỗi ở bất kỳ bước nào:', error));
// Output sau ~1.5 giây: "Sản phẩm: Laptop - 1500 USD"

Promise Combinators

Promise.all() — Chờ tất cả cùng lúc (song song)
const p1 = getUser(1);      // 500ms
const p2 = getUser(2);      // 500ms
const p3 = getUser(3);      // 500ms

// Tất cả chạy song song → chỉ mất ~500ms thay vì 1500ms
Promise.all([p1, p2, p3])
  .then(([user1, user2, user3]) => {
    console.log('Tất cả users:', user1, user2, user3);
  })
  .catch(error => {
    console.error('Nếu MỘT promise thất bại, toàn bộ thất bại:', error);
  });

// Promise.race() — lấy kết quả của promise NHANH NHẤT
Promise.race([p1, p2, p3])
  .then(firstResult => console.log('Promise đầu tiên hoàn thành:', firstResult));

// Promise.allSettled() — chờ TẤT CẢ, không quan tâm thành công/thất bại
Promise.allSettled([p1, p2, Promise.reject('lỗi')])
  .then(results => {
    results.forEach(result => {
      if (result.status === 'fulfilled') {
        console.log('✅ Thành công:', result.value);
      } else {
        console.log('❌ Thất bại:', result.reason);
      }
    });
  });

// Promise.any() — lấy kết quả THÀNH CÔNG đầu tiên (ES2021)
Promise.any([Promise.reject('lỗi 1'), p1, p2])
  .then(firstSuccess => console.log('Thành công đầu tiên:', firstSuccess))
  .catch(err => console.log('Tất cả đều thất bại', err)); // AggregateError
Method Thành công khi Thất bại khi Dùng khi
Promise.all() Tất cả fulfilled Có 1 rejected Cần tất cả kết quả, tất cả phải thành công
Promise.race() Cái nào xong trước Cái nào xong trước (nếu reject) Timeout, lấy server nhanh nhất
Promise.allSettled() Luôn luôn Không bao giờ reject Cần biết kết quả từng cái
Promise.any() Có 1 fulfilled Tất cả rejected Cần 1 thành công, fallback

7. async/await — Đỉnh cao của Async JavaScript

async/await là cú pháp sugar trên Promise, được giới thiệu trong ES2017. Nó cho phép viết code bất đồng bộ với phong cách trông như đồng bộ, cực kỳ dễ đọc.

Cú pháp cơ bản async/await
// Hàm async luôn trả về một Promise
async function fetchUser(id) {
  // await dừng hàm tại đây cho đến khi Promise resolve
  const user = await getUser(id);
  return user; // Tự động wrap trong Promise.resolve(user)
}

// Arrow function async
const fetchUserArrow = async (id) => {
  const user = await getUser(id);
  return user;
};

// So sánh Promise chain vs async/await
// ❌ Promise chain (vẫn tốt, nhưng verbose hơn)
function loadUserDataPromise(userId) {
  return getUser(userId)
    .then(user => getOrders(user))
    .then(orders => getProduct(orders[0]))
    .then(product => ({ user: userId, product }));
}

// ✅ async/await (dễ đọc hơn)
async function loadUserData(userId) {
  const user    = await getUser(userId);
  const orders  = await getOrders(user);
  const product = await getProduct(orders[0]);
  return { user, product };
}

try/catch/finally với async/await

Xử lý lỗi bằng try/catch
async function loadData() {
  try {
    const user = await getUser(1);
    console.log('User:', user);

    const orders = await getOrders(user);
    console.log('Orders:', orders);

  } catch (error) {
    // Bắt lỗi từ bất kỳ await nào trong try block
    console.error('Có lỗi:', error.message);
  } finally {
    // Luôn chạy dù thành công hay thất bại
    console.log('Kết thúc — ẩn loading spinner chẳng hạn');
  }
}

Sequential vs Parallel với async/await

Sequential vs Parallel — sự khác biệt về hiệu năng
// ❌ Sequential — Chạy nối tiếp, CHẬM (tổng thời gian = tổng các bước)
async function loadSequential() {
  const user1 = await getUser(1); // 500ms
  const user2 = await getUser(2); // 500ms (chờ user1 xong rồi mới chạy)
  const user3 = await getUser(3); // 500ms
  // Tổng: ~1500ms ❌
  return [user1, user2, user3];
}

// ✅ Parallel — Chạy song song, NHANH (tổng thời gian = bước chậm nhất)
async function loadParallel() {
  // Khởi động tất cả cùng lúc, không await ngay
  const p1 = getUser(1);
  const p2 = getUser(2);
  const p3 = getUser(3);
  // Chờ tất cả cùng lúc
  const [user1, user2, user3] = await Promise.all([p1, p2, p3]);
  // Tổng: ~500ms ✅
  return [user1, user2, user3];
}

// Top-level await (ES2022) — dùng được trong modules (.mjs)
// Không cần bọc trong async function nữa!
const config = await fetch('/config.json').then(r => r.json());
console.log(config);
✅ Quy tắc

Khi các tác vụ không phụ thuộc vào nhau, hãy dùng Promise.all() để chạy song song. Chỉ dùng await nối tiếp khi kết quả của bước trước cần thiết cho bước sau.

8. Fetch API — Gọi HTTP Request

fetch() là API tích hợp sẵn trong trình duyệt (không cần cài thêm thư viện) để thực hiện HTTP requests. Nó trả về một Promise.

Cú pháp cơ bản — GET request
// fetch() trả về Promise<Response>
const response = await fetch('https://api.example.com/users');

// Response object có nhiều thuộc tính và phương thức hữu ích
console.log(response.status);     // 200, 404, 500, v.v.
console.log(response.ok);        // true nếu status 200-299
console.log(response.statusText); // "OK", "Not Found", v.v.
console.log(response.headers);   // Headers object

// Đọc body — phải gọi một trong các phương thức sau:
const json = await response.json();   // Parse JSON (phổ biến nhất)
const text = await response.text();   // Plain text
const blob = await response.blob();   // Binary data (ảnh, file)
GET, POST — với xử lý lỗi đúng cách
// ❌ Lỗi phổ biến: fetch không reject khi HTTP error (404, 500)!
try {
  const res = await fetch('https://api.example.com/not-found');
  // res.ok = false, res.status = 404
  // Nhưng fetch KHÔNG throw error → catch block KHÔNG chạy!
} catch (e) {
  // Chỉ chạy khi có network error (mất mạng, CORS, v.v.)
}

// ✅ Cách đúng: kiểm tra response.ok
async function apiFetch(url, options = {}) {
  const response = await fetch(url, options);

  if (!response.ok) {
    // Throw error với thông tin từ server
    const errorBody = await response.text();
    throw new Error(`HTTP ${response.status}: ${errorBody}`);
  }

  return response.json();
}

// POST request — gửi dữ liệu lên server
async function createUser(userData) {
  const newUser = await apiFetch('https://api.example.com/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer my-token-123',
    },
    body: JSON.stringify(userData),
  });
  return newUser;
}

// Dùng
try {
  const user = await createUser({ name: 'Bình', email: 'binh@test.com' });
  console.log('Đã tạo user:', user);
} catch (error) {
  console.error('Lỗi tạo user:', error.message);
}

9. Ví dụ thực tế — JSONPlaceholder API

JSONPlaceholder là API miễn phí để thực hành — không cần tạo tài khoản, không cần server.

Gọi JSONPlaceholder API thực tế
const BASE_URL = 'https://jsonplaceholder.typicode.com';

// Lấy danh sách posts
async function getPosts() {
  const response = await fetch(`${BASE_URL}/posts`);
  if (!response.ok) throw new Error(`Lỗi: ${response.status}`);
  return response.json(); // Trả về mảng 100 posts
}

// Lấy post theo ID
async function getPostById(id) {
  const response = await fetch(`${BASE_URL}/posts/${id}`);
  if (!response.ok) throw new Error(`Post ${id} không tồn tại`);
  return response.json();
}

// Lấy comments của một post
async function getCommentsForPost(postId) {
  const response = await fetch(`${BASE_URL}/posts/${postId}/comments`);
  if (!response.ok) throw new Error(`Không lấy được comments`);
  return response.json();
}

// Lấy post và comments song song
async function getPostWithComments(postId) {
  const [post, comments] = await Promise.all([
    getPostById(postId),
    getCommentsForPost(postId),
  ]);

  return { ...post, comments };
}

// Thực thi
(async () => {
  try {
    console.log('Đang tải...');
    const postDetail = await getPostWithComments(1);
    console.log('Tiêu đề:', postDetail.title);
    console.log('Số comments:', postDetail.comments.length);
  } catch (err) {
    console.error(err.message);
  }
})();

Bài tập — Gọi API và hiển thị danh sách bài viết

Viết ứng dụng JavaScript hoàn chỉnh: lấy danh sách 10 bài viết đầu tiên từ JSONPlaceholder và hiển thị lên trang HTML.

index.html
<!DOCTYPE html>
<html lang="vi">
<head>
  <meta charset="UTF-8">
  <title>Danh sách bài viết</title>
  <style>
    body { font-family: sans-serif; max-width: 700px; margin: 40px auto; padding: 0 20px; }
    .post-card { border: 1px solid #ddd; border-radius: 8px; padding: 20px; margin: 16px 0; }
    .post-card h3 { margin: 0 0 8px; text-transform: capitalize; }
    .post-card p { color: #555; margin: 0; }
    #loading { text-align: center; color: #888; }
    #error { color: red; }
  </style>
</head>
<body>
  <h1>📰 Danh sách bài viết</h1>
  <div id="loading">Đang tải...</div>
  <div id="error"></div>
  <div id="post-list"></div>

  <script>
    const loadingEl  = document.getElementById('loading');
    const errorEl    = document.getElementById('error');
    const postListEl = document.getElementById('post-list');

    function renderPost(post) {
      return `
        <div class="post-card">
          <h3>#${post.id} — ${post.title}</h3>
          <p>${post.body}</p>
        </div>
      `;
    }

    async function loadPosts() {
      try {
        const response = await fetch(
          'https://jsonplaceholder.typicode.com/posts?_limit=10'
        );

        if (!response.ok) {
          throw new Error(`Lỗi server: ${response.status}`);
        }

        const posts = await response.json();

        // Hiển thị danh sách
        postListEl.innerHTML = posts.map(renderPost).join('');

      } catch (error) {
        errorEl.textContent = `❌ ${error.message}`;
      } finally {
        loadingEl.style.display = 'none'; // Ẩn loading dù thành công hay lỗi
      }
    }

    loadPosts(); // Gọi khi trang load
  </script>
</body>
</html>

Kết quả mong đợi: Trang hiển thị "Đang tải...", sau đó hiển thị 10 bài viết từ API. Nếu mất mạng, hiển thị thông báo lỗi đỏ.

Thử thêm:

  • Thêm nút "Tải thêm" để lấy 10 bài viết tiếp theo (_start=10&_limit=10)
  • Thêm nút xem chi tiết từng bài viết (gọi /posts/{id})
  • Hiển thị số lượng comments dưới mỗi bài (/posts/{id}/comments)
